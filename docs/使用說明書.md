# Sentinel Mini 使用說明書

## 專案介紹

Sentinel Mini 是在自己電腦執行的 Python 網站設定檢查程式。你可以透過瀏覽器提供網址與檢查目標，查看工具取得的證據，再匯出一份包含設定觀察、重測狀態及修正建議的報告。

這個專案用來示範 AI 規劃、工具執行與獨立確認的分工。Codex 負責選擇任務與分析結果，Python 負責實際請求網站及檢查設定。規則模式使用固定計畫，沒有 Codex 也能完成示範與報告匯出。

## 主要功能

| 功能 | 你可以看到的內容 |
| --- | --- |
| 網站設定檢查 | 指定頁面的 CSP、nosniff 與 Cookie 屬性觀察 |
| HTTPS 連線檢查 | TLS 版本、cipher、憑證到期日與驗證結果 |
| AI 規劃與分析 | 選取任務的理由、工具結果註解與最終摘要 |
| 獨立重測 | 另一次 GET 是否仍出現相同設定，並連結兩次證據 |
| 歷史紀錄 | 網頁版任務、執行狀態及已取得的資料 |
| 報告匯出 | 便於閱讀的 Markdown，以及保留完整結構的 JSON |
| 內建測試網站 | 可比較的設定缺口頁面與修正頁面 |

「可重現」表示程式再次觀察到同一設定，不代表已成功利用漏洞。程式只檢查指定頁面的部分設定，不會登入、爬取全站或測試 SQL injection。TLS 子程序會記錄連線結果，尚未把 TLS 失敗判為獨立漏洞。

## 檢查流程與成果

每項任務先建立計畫，再執行已選取的工具。工具取得回應後，程式保存證據並找出待重測的設定觀察。確認階段另發請求比對結果，AI 模式最後還會產生摘要。

本教學會先用內建網站得到五項可重現觀察，再比對修正頁面預期的零項結果。最後，你會匯出一份有證據索引與修正建議的報告。兩份頁面用來示範已實作的規則，零項結果不表示網站全面安全。

## 操作前準備

下面步驟以 Windows 與預設連接埠為例，需要 Python 3.11 以上。Codex 步驟另需已安裝並登入的 Codex CLI。第一次操作先選規則模式，就能在沒有模型服務的情況下比對固定結果。

## 操作方式

### 1. 啟動本機程式

將 ZIP 解壓縮，進入放有 [`app.py`](../app.py) 與 [`start.bat`](../start.bat) 的資料夾。不要直接從 ZIP 預覽內啟動，也不要只複製其中一個檔案。

在這個資料夾開啟 PowerShell，先確認 Python：

```powershell
python --version
```

版本應為 3.11 或以上。接著執行：

```powershell
python app.py
```

程式本身不需要另外安裝 Python 套件。你也可以點兩下 `start.bat`，它會切換到正確資料夾再啟動。

成功時，終端會顯示：

```text
Sentinel Mini: http://127.0.0.1:8765
Demo target: http://127.0.0.1:8766/
Ctrl+C to stop.
```

瀏覽器通常會自動開啟。若沒有，手動前往[本機操作介面](http://127.0.0.1:8765)。`127.0.0.1` 指目前這台電腦；`8765` 是操作介面，`8766` 是內建測試網站。

請保留啟動程式的終端視窗。關閉視窗或按下 Ctrl+C 會停止服務，瀏覽器頁面也就無法繼續讀取任務。

### 2. 完成第一個檢查任務

建立第一項任務時，依序操作：

1. 在 **建立檢查任務** 按 **填入本機測試網站**。目標應顯示 `http://127.0.0.1:8766/`，檢查說明也會自動填入。
2. 將執行模式改成 **規則模式 · 免模型示範**。
3. 勾選 **我擁有此網站，或已取得檢查授權**。
4. 按 **開始檢查**，等待執行工作區顯示任務狀態。

這次先用規則模式，是為了得到固定、容易比對的結果。它會建立三類任務，不會呼叫 Codex，也不消耗模型用量。

執行工作區會依序顯示規劃、執行與確認。網站掃描檢查安全標頭，送出請求檢查 Cookie 屬性，確認階段則重新發出 GET 請求，比對同樣的設定是否仍然存在。

「執行指令」會顯示略過，這是預期結果。內建網站使用 HTTP，沒有 TLS 憑證可檢查；只有 HTTPS 目標才會啟動固定的 TLS 子程序。

### 3. 檢查五項預期結果

任務結束後，整體狀態應為「已完成」，右側應顯示五項「可重現」的設定觀察：

| 設定觀察 | 這次檢查到的情況 |
| --- | --- |
| 未設定 Content-Security-Policy | HTML 回應沒有 CSP 標頭 |
| 未啟用 nosniff | 沒有設定 `X-Content-Type-Options: nosniff` |
| `demo_session` 未設定 HttpOnly | 此 Cookie 沒有限制 JavaScript 讀取 |
| `demo_session` 未設定 Secure | 此 Cookie 沒有限制僅在 HTTPS 傳送 |
| `demo_session` 未明確設定 SameSite | 此 Cookie 沒有明確指定跨站傳送規則 |

這個網站刻意保留上述設定缺口，因此結果只是教學資料。缺少 CSP 不能直接證明 XSS，缺少 SameSite 也不能直接證明 CSRF。

往下展開「證據資料」。這次應有三筆 HTTP 證據，分別來自掃描、Cookie 請求與獨立重測。每筆都有自己的證據 ID，結果中的 ID 可用來對照原始觀察與重測資料；Cookie 的值會顯示為 `[REDACTED]`。

若沒有出現這些結果，先確認模式是「規則模式」、目標是首頁而不是 `/fixed`，再查閱[操作指南的排錯方式](操作指南.md)。

### 4. 比對修正後的頁面

將目標改成 `http://127.0.0.1:8766/fixed`，保留規則模式，再建立一項任務。這個頁面補上了上述標頭與 Cookie 屬性，因此預期為零項觀察。

兩次結果的差別，顯示程式確實比對回應設定。零項只表示這些規則沒有產生觀察，並不表示網站所有功能都安全。

### 5. 改用 Codex 分析

這一步會使用模型服務。程式會送出目標、檢查說明、遮蔽後標頭與觀察，不會送出網頁本文。先確認這些資料適合交給你的模型服務，也不要在檢查說明輸入密碼或金鑰。

如果你已經使用 Codex CLI，在另一個 PowerShell 視窗確認登入狀態：

```powershell
codex login status
```

尚未登入時，可執行 `codex login` 依 CLI 提示登入。Sentinel Mini 沿用 CLI 的既有登入，不需要你把登入憑證或 API Key 貼進網頁。

回到操作介面，按「填入本機測試網站」，再將模式切成「Codex AI · 沿用本機登入」並開始檢查。Codex 會選擇任務並提供理由，Python 執行工具後，Codex 再分析結果與撰寫摘要。

AI 模式可能選擇部分任務，因此不保證每次都有五項結果。它最多進行五次模型呼叫，每次 Codex 呼叫最多等待 150 秒；實際速度取決於模型與服務狀態。模型用量依你的帳戶方案計算。

介面顯示「已偵測到 Codex CLI」只代表找到執行檔，不代表登入或模型連線已通過驗證。若選項不能使用，或任務顯示失敗，依[Codex 排錯流程](操作指南.md)處理。尚未安裝 CLI 時，可以先完成規則模式的教學。

### 6. 匯出一份報告

選取剛才完成的任務，按「匯出報告 ↓」。瀏覽器會下載名稱類似 `sentinel-xxxxxxxx.md` 的 Markdown 檔案。這份報告包含目標、執行任務、設定觀察、重測狀態、修正建議與證據索引。

再按「匯出 JSON ↓」保存完整資料。Markdown 適合閱讀與說明，JSON 才包含擷取的 HTTP 標頭、本文片段及完整結構。完整報告欄位與狀態意義可查閱[參數與結果參考](參數與結果參考.md)。

下載完成後，確認報告中的目標、狀態與介面一致。到這一步，你已完成一次從建立任務到取得報告的流程。

### 7. 結束並保留紀錄

在原本啟動程式的終端按 Ctrl+C。下次從同一份專案重新啟動，網頁版任務會從 `data/runs.sqlite3` 讀回，左側最多顯示最近 100 筆。

如果程式上次在任務中途停止，重啟後會標記「已中斷」，保留已取得的證據。程式不會自動重送工具；需要繼續時，建立一項新任務。

接下來若要檢查自己有權限的網站、使用命令列或備份紀錄，請前往[操作指南](操作指南.md)。設定值與結果欄位集中在[參數與結果參考](參數與結果參考.md)。若要理解為何可重現不等於已證明漏洞，請閱讀[流程與限制](流程與限制.md)。
